BdagPool Template Reset Error Propagation

This plan targets a narrow source-level stability gap in the mining template path: BdagPool.updateTemplate can currently hide failed rebuilds, while ResetTemplate() reports success to the miner even when no healthy EVM pending block was produced.

Repo: blockdag-corechain Branch: feature/corechain-bdagpool-reset-errors Risk: node-only, source-only Live action: none

Why This Matters

Current Failure Shape

The miner asks BdagPool to reset its EVM pending template before building a DAG mining template. If BdagPool cannot prepare, fill, or commit that pending block, the caller gets no reliable error.

Mining Impact

Hidden failures make the pool and watchdog infer state from stale submissions, expired templates, or missing work. That delays recovery and can waste ASIC hash power on unusable templates.

Safe Fix

Propagate rebuild errors, make explicit resets force a rebuild, keep the last usable pending state when rebuild fails, and record the exact failure reason in mining template health.

Implementation Shape

1. Return errorsupdateTemplate returns an error instead of silently exiting.
2. Reset reply carries errorresetTemplateMsg replies with error, not only an empty signal.
3. Force explicit resetResetTemplate() bypasses the parent-match no-op path so reset means rebuild now.
4. Preserve last goodA failed rebuild discards the new environment and does not replace current.
5. Miner records causeupdateBlockTemplate records BdagPool reset failures as template build errors.

Acceptance Criteria

  • ResetTemplate() returns a real error when BdagPool is stopped, syncing, interrupted, or rebuild fails.
  • ResetTemplate() forces a template rebuild even when the previous pending block has the current parent.
  • updateTemplate does not replace the current environment after commit failure.
  • Successful rebuild behavior remains unchanged.
  • Miner template health exposes reset failures as evm_pending_template_unavailable.
  • Nodeworker treats that reason as restart-eligible only when the health result marks the error blocking.
  • Focused offline tests pass; no live services or ASICs are touched.
