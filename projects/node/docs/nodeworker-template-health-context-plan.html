Nodeworker Template Health Context

Repo: blockdag-corechain Branch: feature/corechain-nodeworker-template-health-context Base: feature/corechain-p2p-freshness-metrics Risk: low

This task makes nodeworker readiness warnings carry the source-level mining health context already exposed by the miner API.

Problem

PRs #19 and #20 expose template build latency and P2P freshness through getTemplateHealth, but nodeworker still logs only the older mineable/submit-ready fields.

Goal

Decode the advisory fields and include them in readiness failure context so operators and watchdogs can see whether a warning is template-age, build-latency, or P2P-freshness related.

Safety Boundary

Do not make stale P2P freshness restart-eligible by itself. This branch is log/context enrichment only.

Outcome

Future incidents should have richer source-level context without changing node behavior, consensus, peer selection, or mining policy.

Fields To Surface

  • template_age_ms, last_good_template_age_ms, latest_template_seq.
  • last_template_build_duration_ms, last_template_build_reason, last_template_build_error_code.
  • p2p_mining_fresh, p2p_mining_fresh_reason_code, consensus peer counts, peer lead, and graph-state ages.

Definition Of Done

  • Design committed before code changes.
  • Nodeworker decodes the new fields without requiring them from older nodes.
  • Readiness failure text includes advisory context only when meaningful.
  • Tests prove advisory P2P/build fields do not change restart eligibility.
  • Focused nodeworker/miner tests and relevant package tests pass.
