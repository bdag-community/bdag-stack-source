P2P Peer Freshness Observability

This branch exposes how fresh the node’s connected consensus peers are without changing sync peer selection, routing, disconnect behavior, or mining policy. The goal is to replace watchdog guesswork with source-level freshness signals.

The legacy p2p/freshness/* gauges remain populated as aliases during rollout so existing dashboards do not lose telemetry while consumers move to the mining-specific names.

Why

Template freshness depends on a node seeing chain tips quickly. A node can look generally healthy while its connected peers have stale graph-state updates. These metrics make that condition visible to Grafana and watchdog logic before it turns into expired or late mining submissions.

Acceptance Criteria

  • Metrics are aggregate gauges with fixed names and no peer IDs, IPs, wallets, or high-cardinality labels.
  • getTemplateHealth includes the same peer-freshness snapshot, plus explicit p2p_mining_fresh, p2p_mining_fresh_reason_code, and p2p_sync_peer_present fields for dashboard/watchdog consumers.
  • Peer selection and sync behavior are unchanged.
  • Unit tests cover freshness snapshot counts and stale-age calculation.
  • Package tests pass for p2p/peers, p2p/synch, and related P2P packages.
