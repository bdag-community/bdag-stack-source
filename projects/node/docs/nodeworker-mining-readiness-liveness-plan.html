Nodeworker Mining Readiness Liveness Gate

The node can be process-alive and HTTP-healthy while mining is degraded. This branch adds an optional nodeworker gate that polls getTemplateHealth and only forces recovery after sustained non-mineable or non-submit-ready state.

Explicit source signal Feature-flagged No live changes

Behavior

Normal Liveness

Keep the existing /healthz liveness check unchanged.

Mining Readiness

Optionally poll DAG RPC getTemplateHealth. A healthy mining node must be mineable_now=true and submit_ready=true.

Anti-Churn

The worker only restarts after the bad state persists longer than health.mining-readiness-timeout. A single good probe resets the timer.

Configuration

FlagDefaultReason
--health.mining-readiness-timeout0Disabled by default so packaged deployments opt in after validating the node health contract.
--health.mining-readiness-grace2mPrevents startup and sync transitions from forcing unnecessary node restarts.

Definition Of Done

  • Nodeworker can parse successful and unhealthy getTemplateHealth responses.
  • Sustained restart-eligible mining readiness failure triggers the same diagnostic dump and controlled shutdown callback as liveness failure.
  • Grace period and warning-only states prevent restart churn during startup, syncing, auth mistakes, unsupported RPC methods, and malformed health responses.
  • Transient mining readiness failure recovers without restart.
  • DAG RPC auth and timeout behavior reuse existing nodeworker DAG RPC configuration.
