Mining Template Latency Instrumentation

This branch adds passive timing around the mining-template hot path so later performance work is driven by evidence instead of guesswork. It does not change block contents, parent selection, state-root calculation, submit behavior, or live service configuration.

Repo: blockdag-corechain Branch: feature/corechain-template-build-latency Risk: read-only source behavior Live action: none

Why This Comes First

Template Build Is Consensus Adjacent

State roots, merkle roots, parent sets, and template validation are expensive places to optimize blindly. Timing the existing path lets us identify the slow stage before touching logic.

ASIC Hash Power Is Time Sensitive

The chain produces blocks roughly every second. Every avoidable template delay reduces the useful lifetime of work distributed to miners.

Safe For Review

Low-cardinality timers are easy for Ben to review and give us a stable baseline before state-root or GBT allocation changes.

Acceptance Criteria

  • All new signals are passive timers or gauges with fixed names and no per-wallet, per-IP, or per-template labels.
  • No consensus output changes: block header, parents, state root, tx root, timestamp, and difficulty logic are unchanged.
  • Instrumentation compiles with existing metrics infrastructure and does not require live service changes.
  • Focused package tests pass for miner, mining, BdagPool, nodeworker, and RPC client command packages.
